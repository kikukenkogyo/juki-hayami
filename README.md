# 重機早見表

菊建興業が保有する重機34台と、アタッチメント91台（76機種）の寸法・重さ・能力を、iPhone・iPad ですぐ見るためのアプリです。

- 一番上の「重機｜アタッチメント」で切り替え
- 重機の詳細の一番下「このクラスに付くアタッチメント」で、同じクラスのアタッチメント一覧へ飛べる
- 「現場条件チェック」に通る所の幅・高さの制限・重さの制限・作業場所の幅を入れると、全台に ○（通れる）△（ぎりぎり）？（データなし）×（通れない）が付く（2026-10-27〜）
  - △＝余裕が合計300mm未満（作業場所は片側150mm未満）。重さは○か×だけで、アタッチメントを付けない重さで見る
  - 作業場所は「後端旋回半径が幅の半分に収まるか」。真ん中に置いた目安で、壁寄せは見ていない
  - 「2.4」「2.4メートル」はメートル、「8000」「8000kg」はkgとして読む（キーボードのマイクで話して入れられる）
  - 判定の決まりは `lib.js` の `judgeMachine`、試験は `test/site.test.mjs`
- 重機・アタッチメントの**今の所在**を出す（2026-11-11〜）。Notion から30分ごとに自動で読む
  - 重機は「重機情報」の所在地（管理番号でつなぐ）。アタッチメントは「アタッチメント情報」の現在地（空なら所在地）を Notion の管理番号（A-001〜）でつなぎ、名前も合っているか確かめる（合わない台は所在を出さず「要確認」）
  - **使えるかどうか**も出す（2026-11-11〜）。Notion の数式をそのまま使う: 重機は「現在状態」、アタッチメントは「状態」（🟢正常 / 🟡不良 / 🔴故障 / 🔧修理中）。故障報告の無い重機は正常。くわしくは最新報告区分（要観察（使用可）・修理依頼中など）と修理予定・故障内容
  - 現場条件チェックの「空いている重機だけ」＝所在が置き場・工場・アキコ（Notion の「空いている重機」ビューと同じ）
  - しくみ: `.github/workflows/publish.yml` が、公開の直前に `tools/fetch_locations.mjs` で `locations.json` を作る。**所在はリポジトリに入れない**（履歴に残さないため。.gitignore 済み）
  - 必要な設定（最初の1回）: ① Settings → Pages → Source を「GitHub Actions」 ② Notion で内部インテグレーションを作り、キクケンページ一式（重機情報・アタッチメント情報の親）に接続 ③ その鍵を Settings → Secrets and variables → Actions に `NOTION_TOKEN` で入れる
  - 読めなかったときは、公開中の所在をそのまま使う（画面の「○時点」が古くなる。2時間より古いと「古いかもしれません」と出る）
  - 60日間リポジトリに変更がないと、GitHub が30分ごとの実行を止める。メールが来たら Actions の画面で「Enable workflow」
- Claude の「重機選び」プロジェクト（声で相談する窓口）に入れる表は `node tools/make_claude_files.mjs <出力フォルダ>` で作る（出力先は `AI作業場\重機選びプロジェクト\`）。データを直したら作り直して、プロジェクトのファイルを入れかえる。指示文も同じフォルダにある

- 公開アドレス: https://kikukenkogyo.github.io/juki-hayami/
- 元のカタログ PDF: `OneDrive\Desktop\AI作業場\重機・アタッチメント情報\`

## iPhone・iPad で使う

1. Safari で公開アドレスを開く
2. 下の「共有」ボタン（四角から矢印が出ているマーク）を押す
3. 「ホーム画面に追加」を押す → 右上の「追加」
4. ホーム画面のピンクのアイコンから開く

一度開けば、電波の悪い現場や地下でも見られます。

- ホーム画面に追加したら、**電波のある所でアイコンから一度開いておく**（Safariで開いた分とは別に保存されるため）
- 電波が弱いときは3秒待って、手元に保存した内容を出します
- データを直したあとは、電波のある所で開くと新しくなります（画面の作りの変更は、2回目に開いたときに反映）

## 数字を直したいとき・重機が増えた／減ったとき

Claude に「重機早見表の○番の全幅を○○に直して」「○○を重機早見表に追加して」と頼む。

Claude がやること:

- 数字は `juki.json` だけを直す（`index.html` は触らない）
- 追加は `tools/mapping.json` に台を足し、カタログを読んで `juki.json` に追加、`python -X utf8 -I tools/make_images.py <PDFフォルダ>` でページ画像を作る
- `node --test "test/*.test.mjs"` を通す（データの形・34台・画像の実在も検査する）
- 画面のファイルや画像は自動で新しくなる。`sw.js` の保存の仕方そのものを変えたときだけ `VERSION` を上げる
- `git commit` → `git push`（反映まで1〜2分）

## アタッチメントの数字を直したいとき・増えた／減ったとき

Claude に「重機早見表のアタッチメント ○○ の重量を○○に直して」「○○をアタッチメントに追加して」と頼む。

Claude がやること:

- 数字は `att.json` だけを直す（理由は `tools/att_resolve.json` に書き足す）
- 追加は `tools/att_mapping.json` に機種（または管理番号）を足し、カタログがあれば読んで `att.json` に追加、`python -X utf8 -I tools/make_images.py <PDFフォルダ> att` でページ画像を作る
- 台帳は Notion（アタッチメント情報）が正。管理番号は Notion と同じ A-001〜（units には数字で 1〜）。2026-11-11 に Notion の91台に合わせ、Notion に無い7機種（MR1800・MR1300・マグナム1800・マグナム1200・アイアンクロー500・TS-WB950V-F・TS-W1100V（フリー））を外した（画像ファイルは img/ に残してある）
- Notion で台が増えた・減った・番号が変わったときは、公開中の locations.json を保存して `node tools/att_sync.mjs <保存したファイル>` で違いを見る → 外す機種を酒井さんに確認 → `--apply`。名前で決められない台は `tools/att_sync_pins.json` に「Notionの番号: 機種の id」で決める（A-025＝TS-W950V①＝シリンダーカバーなし、A-026＝②＝ふつう。2026-11-11 酒井さん）
- `node --test "test/*.test.mjs"` を通す（台数91台・画像の実在も検査する。台数が変わったら `test/att.test.mjs` の 91 と `test/locations.test.mjs` の 91 も直す）
- `git commit` → `git push`

## 中身

| ファイル | 役割 |
|---|---|
| `juki.json` | 重機34台のデータ |
| `att.json` | アタッチメント76機種のデータ |
| `img/` | カタログのページ画像 |
| `index.html` `style.css` `app.js` | 画面 |
| `lib.js` | 検索・絞り込み |
| `sw.js` `manifest.json` | 電波なし対応・ホーム画面アイコン |
| `tools/` | データづくりの道具と記録（対応表、2回読みの結果、食い違いの決め方。アタッチメントは `att_` で始まるもの） |
| `docs/` | 設計書・作業手順書 |
