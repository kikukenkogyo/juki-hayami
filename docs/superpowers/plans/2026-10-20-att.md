# 重機早見表 第2弾（アタッチメント） Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 保有アタッチメント（Notion 台帳 102 台）を機種ごとにまとめ、重機早見表アプリの「アタッチメント」タブで検索・表示でき、電波なしでも見られるようにする。

**Architecture:** 第1弾と同じ作り。データは新しい `att.json`（`juki.json` は触らない）、検索・整形は `lib.js` の純粋関数（`node:test` で試験）、画面は `app.js` に切替タブとアタッチメントの一覧・詳細を足す。数字は Claude が PDF を画像で2回読み、`tools/compare.mjs` で突き合わせ、食い違いは `tools/att_resolve.json` のルールで解消する。

**Tech Stack:** HTML/CSS/素の JavaScript（ES モジュール）、Node 24（`node:test`、外部パッケージなし）、Python 3.12 + PyMuPDF（ページ画像化のみ）、GitHub Pages。

**Spec:** `docs/superpowers/specs/2026-10-20-att-design.md`

## Global Constraints

- 外部ライブラリ・外部サーバーは使わない
- 単位: 長さ mm、アタッチメントの重さ kg（カタログどおり）、力 kN、油量 L/min、圧力 MPa、打撃数 回/分
- 換算: 1 tf = 9.80665 kN、1 kgf/cm² = 0.0980665 MPa。換算したら元の数字を注記に残す（例「150tf を換算」）
- 範囲の数字は `[小, 大]` で持ち、「100〜150 L/min」と出す
- 読めなかった値は `v: null` + `note: "カタログに記載なし"`。カタログ自体が無い機種は `catalog: false` で、画面は「カタログなし」
- 所在地・状態・故障内容は載せない
- Notion 台帳 `C:\Users\shuta\OneDrive\Desktop\AI作業場\管理システム構築\notion_アタッチメント\extracted\att_all.csv` を正。PDF・番号・クラスのずれは推測で決めず酒井さんに確認
- PDF は `C:\Users\shuta\OneDrive\Desktop\AI作業場\重機・アタッチメント情報\`。リポジトリには自社機種のページ JPEG（横1200px、品質70、`tools/render_pages.py`）だけ入れる
- 重機側（`juki.json`・重機の一覧と詳細の動き）は変えない。足すのは重機詳細の「このクラスに付くアタッチメント」ボタンだけ
- 作業ブランチ `att`。push は酒井さんの了承を取ってから

- Produces: `tools/att_mapping.json` = 配列。1要素 `{ "id": string, "name": string, "kind": string, "class": number, "maker": string, "units": number[], "memo": string, "pdfs": [{ "file": string, "pages": number[] }], "flag": string }`

- [ ] **Step 2:** PDF 約30件（「管理番号」で始まらないもの）の中身を画像で見て、各機種に `pdfs` と該当ページ（仕様表・寸法図）を割り当てる。型式違い（例 台帳 `TOP210` ↔ カタログ `TOP210B`、`MKB500N` ↔ `MKB500N2`、`GH-10` ↔ GHシリーズ、`TS-W650XCV` ↔ `TS-W650`、`ONI150` ↔ `オニムシ150`、`マグナム1400` ↔「坂戸小割0.7」）や、同じ名前で番号・クラスが重なる所は `flag` に理由を書く。カタログが無い機種は `pdfs: []`、`flag: ""`

- [ ] **Step 4:** 回答を反映して `flag` を空にする。回答で台帳と変える所は `memo` ではなくこのファイルの `units`・`class` に入れ、回答の要約を `tools/att_resolve.json` の `rules` に書く（Task 3 で作るファイルを先に作ってよい）
