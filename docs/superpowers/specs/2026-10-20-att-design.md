# 重機早見表 第2弾（アタッチメント） 設計書

- 作成日: 2026-10-20（ノートPC）
- 依頼者: 酒井（株式会社菊建興業 代表）
- 前提: 第1弾（重機34台、`2026-10-20-juki-hayami-design.md`）は公開済み・使い心地も問題なし
- 状態: 設計案 承認済み → この設計書の確認待ち

## 1. 目的

打ち合わせ中や出先で、保有アタッチメント（圧砕機・小割機・カッター・ブレーカ・つかみ機など）の重さ・大きさ・能力・付けられる重機を、第1弾と同じアプリから数秒で確認できるようにする。

- うまくいった状態: アイコン1タップ →「アタッチメント」に切替 → 機種名・クラス・種類で絞る → 数字が見える。重機の詳細から「このクラスに付くアタッチメント」へ1タップで飛べる。電波なしでも見られる

## 2. 決まったこと（2026-10-20 酒井さん回答）

- 載せる項目: 重さ・大きさ／口の大きさ・力／付けられる重機／油圧・配管 の全部
- 画面: 上に「重機｜アタッチメント」の切替ボタン＋重機の詳細から飛べるボタン
- 台帳: Notion（`AI作業場\管理システム構築\notion_アタッチメント\extracted\att_all.csv`、102行）を正とする。Excel（`アタッチメント一覧.xlsx`）は参考
- 一覧の単位: 機種ごとに1枚（同じ機種の複数台は「保有○台」にまとめる）

## 3. 範囲

- 載せるもの: Notion 台帳のアタッチメント全部（売却検討・故障中も含む。状態は出さない）
- 載せないもの: 所在地・状態・故障内容（日々変わる。Notion が正）、重量などでの絞り込み（必要になったら後で）
- `juki.json`（重機）は触らない

## 4. 画面

### 切替
- 一番上に「重機｜アタッチメント」の2つのボタン。押した方の一覧に切り替わる
- 今どちらを見ているかはアドレスの `#` で覚える（戻るボタン・再読み込みで元に戻る）

### アタッチメント一覧
- 検索窓: 機種名・メーカー・管理番号・仕様の一部（例「1100」「オカダ」「5本」）
- クラスボタン: 0.1／0.25／0.45／0.7／1.2／1.6（重機と同じ）
- 種類ボタン: 圧砕（クラッシャー）／SRC／小割／カッター／ブレーカ／つかみ（グラップル）／その他（マグネット・コアマン・リキヤ）
- カード: 機種名・メーカー・クラス・種類・保有○台・重量・開口幅（ブレーカはチゼル径）
- 並び順: クラス小さい順 → 種類順 → 機種名順

### アタッチメント詳細
- 本体: 質量（kg）、全長、全幅、全高（格納時）
- 能力: 最大開口幅、破砕力または切断力（kN）／ブレーカは打撃数（回/分）・チゼル径（mm）
- 付けられる重機: 適合ベースマシン（○〜○t）、台帳のクラス
- 油圧・配管: 必要油量（L/min）、使用圧力（MPa）、旋回（有・無・フリー）、配管の本数
- 保有: 管理番号の一覧（例「No.17・18・19…」）、台帳の備考（例「0.25と0.45兼用機」）
- カタログのページ画像（拡大可）、出典（ファイル名・ページ・どの表か）
- 読み取れなかった項目は「カタログに記載なし」、カタログ自体が無い機種は「カタログなし」と表示（空欄にしない）
- 「要確認」の数字には印を付ける

### 重機の詳細に追加
- 「このクラス（○㎥）に付くアタッチメント」ボタン → アタッチメント一覧がそのクラスだけ選ばれた状態で開く

### 表示の決まり
- 長さ mm、アタッチメントの重さ kg（カタログどおり）、力 kN、油量 L/min、圧力 MPa
- 範囲の数字（例: 油量 100〜150）は「100〜150 L/min」と範囲のまま出す
- カタログが t・kgf・kgf/cm² の場合は換算し、元の数字を注記に残す（1 tf = 9.80665 kN、1 kgf/cm² = 0.0980665 MPa）

## 5. データの作り方

1. 機種のまとめ: Notion 台帳の「名称」で機種ごとにまとめる。「（5本配管）」「（ペンチ刃）」「（フリー）」など仕様違いは別の1枚にする
2. 対応表: 機種 → 使う PDF・ページ。台帳とのずれ（重複番号 12・46・52・94・95、Excel とのクラス違いなど）とカタログの型式違い（例: 台帳 TOP210 ↔ カタログ TOP210B）は推測せず酒井さんに確認
3. 読み取り: PDF を画像にして拡大し、自社機種の欄だけを読む
4. 2回読み（別担当）→ `tools/compare.mjs` で突き合わせ → 食い違いはルールで解消し `tools/att_resolve.json` に記録
5. カタログが無い機種: 台帳の情報（名称・メーカー・クラス・種類・管理番号・備考）だけ載せ、数字は「カタログなし」
6. ページ画像: 自社機種のページだけを `img/att-<機種ID>-<連番>.jpg` に（第1弾と同じ縮小 JPEG）

### att.json の形（1機種分の例。数字は形の説明用）

```json
{
  "id": "ts-w1100v-arts",
  "name": "TS-W1100V ARTS",
  "kind": "圧砕",
  "class": 0.7,
  "maker": "オカダ",
  "units": [17, 18, 19, 20, 21, 22, 23],
  "memo": "",
  "catalog": true,
  "values": {
    "mass_kg":    { "v": 2100,      "note": "",             "check": false },
    "open_mm":    { "v": 1100,      "note": "",             "check": false },
    "force_kn":   { "v": 1470,      "note": "150tf を換算", "check": false },
    "base_t":     { "v": [20, 30],  "note": "",             "check": false },
    "oil_lpm":    { "v": [150, 250],"note": "",             "check": false }
  },
  "source": [{ "file": "TS-350・1100V.pdf", "page": 2, "where": "仕様表" }],
  "images": ["img/att-ts-w1100v-arts-1.jpg"]
}
```

- 項目: `mass_kg` `length_mm` `width_mm` `height_mm` `open_mm` `force_kn` `blows_per_min` `chisel_mm` `base_t` `oil_lpm` `pressure_mpa` `rotation`（文字: 有・無・フリー）`pipes`（本数）
- `v` は数字、範囲なら `[小, 大]`、無ければ `null`（その時は注記必須）

## 6. 仕組み

- 画面: `index.html` に切替ボタンと種類ボタンを足す。`app.js` に一覧・詳細を足す（重機側の動きは変えない）
- 検索・絞り込み: `lib.js` に `filterAtts`・`sortAtts`・範囲の整形を足す。先に試験を書いてから作る
- 電波なし: `sw.js` の保存対象に `att.json` を足し、`juki.json` と同じ「3秒待って保存分」の扱いにする。両方の画像を保存。保存の形が変わるので `VERSION` を上げる
- 検査: `tools/schema.mjs` にアタッチメント用の形の検査を足し、試験で「台帳の全台が att.json のどれかに入っている」「画像が実在する」を確かめる

## 7. 確かめ方

- 試験（`node --test "test/*.test.mjs"`）がすべて合格
- iPhone 幅（375px）で表示確認
- 検索・クラス・種類の絞り込み、重機 → アタッチメントへのボタンが正しく効く
- Edge（headless）で電波なしでも一覧・詳細・画像が出る（アプリ内ブラウザはサービスワーカー不可のため）
- 公開前に酒井さんの了承を取る → 公開後、iPhone で確認してもらう

## 8. やらないこと

- 重量・開口幅での絞り込み
- Notion との自動連携（台帳の追加・削除は手で反映）
- 重機とアタッチメントの「この重機にこれが付く」細かい相性表（クラスでつなぐだけ）
