# 重機早見表アプリ（juki-hayami） 設計書

- 作成日: 2026-10-20（ノートPC）
- 依頼者: 酒井（株式会社菊建興業 代表）
- 状態: 設計①〜③ 承認済み → この設計書の確認待ち

## 1. 目的

打ち合わせ中や出先で、自社保有重機の「搬入・配置の検討に使う寸法と重さ」を、iPhone・iPad から数秒で確認できるようにする。

- 今の困りごと: OneDrive に入る → 72件の PDF からファイルを探す → カタログ内で自社機種の欄を探す、の3段階で時間がかかる
- うまくいった状態: ホーム画面のアイコンを1タップ → 機種名かクラスで絞る → 寸法が見える（10秒以内）。電波の悪い現場でも見られる

## 2. 調査でわかったこと（2026-10-20 時点）

- 元資料: `OneDrive\Desktop\AI作業場\重機・アタッチメント情報\`（PDF 72件、約130MB）
- 約63件は紙のスキャン画像で、文字検索できない → AI が画像として読む必要がある
- カタログ1冊に複数機種が載っているものがある（例: SK350DLC のカタログに SK550D・SK400D も掲載）
- ファイル名の管理番号と Notion 重機台帳の管理番号がずれているものがある
  - 009: ファイル「PC450LC-8」↔ Notion「PC450LC-11」
  - 032: ファイル「CAT320E」↔ Notion「CAT320ERR」
  - 004・005・007・008・012・017・025・026 などは、1つの番号に複数ファイルがある
  - 33番 ZX20U-5A は PDF が無い
  - SK35SR-7 は Notion で管理番号が空欄
- Notion 重機台帳の書き出し: `AI作業場\管理システム構築\juki_info_all.csv`（機種名・クラス・仕様・管理番号など）

## 3. 範囲

- 第1弾: 重機（Notion 台帳の34台）のみ
- 第2弾（使ってみて良ければ）: アタッチメント（重量・開口幅・取付クラス）
- 載せないもの: 所在地・点検日・状態など日々変わる情報（Notion が正）

## 4. 画面（設計①）

### 一覧画面
- 検索窓: 機種名・仕様・管理番号の一部で絞り込み（例「228」「ロング」「クレーン」）
- クラスボタン: 0.1／0.25／0.45／0.7／1.2／1.6（タップで絞り込み、もう一度で解除）
- 条件絞り込み: 「全幅 ○mm以下」「全高 ○mm以下」「重量 ○t以下」
  - 値が「カタログに記載なし」の機種は、条件絞り込み時は除外せず末尾に「寸法不明」として出す
- カード: 管理番号・機種名・仕様・全幅・全高・重量
- 並び順: クラス小さい順 → 管理番号順

### 詳細画面（カードをタップ）
- 本体: 運転質量、全幅、全高（輸送時）、全長（輸送時）、クローラ幅（シュー幅）、後端旋回半径、接地圧
- 作業範囲: 最大作業高さ、最大作業半径、最大掘削深さ
- クレーン仕様の機種のみ: つり上げ荷重（最大）
- 各数字にカタログの注記（「輸送時」「シュー幅600mm時」など）を小さく添える
- 読み取れなかった項目は「カタログに記載なし」と表示（空欄にしない）
- 「要確認」の数字には印を付ける
- 「カタログのページを見る」: 自社機種の寸法図・仕様表のページ画像（拡大可）

### 表示の決まり
- 長さは mm、重さは t（小数1桁）、接地圧は kPa
- 文字は大きめ、片手で操作できる配置

## 5. データの作り方（設計②）

1. 対応表づくり: Notion 台帳34台を「正」とし、Claude が「管理番号 → 使う PDF・ページ」の対応表を作る。ずれ・重複・PDF無しに印を付け、酒井さんに印の所だけ確認してもらう（推測で決めない）
2. 読み取り: PDF を画像にして拡大し、自社機種の欄だけを読む。同じカタログの別機種は拾わない
3. 出典の記録: 1台ずつ「ファイル名・ページ・どの表か」を記録する
4. 2回読みの照合: 2回読み取り、食い違った数字は「要確認」にする
5. 確認: 「要確認」一覧を酒井さんに見てもらってから公開する
6. 原本の扱い: PDF 一式はネットに載せない。自社機種の寸法図・仕様表のページだけを画像（縮小・JPEG）にして載せる。元の PDF は OneDrive にそのまま置く
7. 更新: 重機の購入・売却時は「○○を追加して」で、Claude が PDF を読んで `juki.json` に追加 → 公開まで行う

## 6. 仕組みと置き場（設計③）

- 保管場所: GitHub `kikukenkogyo/juki-hayami`、ローカルは `C:\Users\shuta\Documents\juki-hayami`（2台共通ルール）
- 公開: GitHub Pages `https://kikukenkogyo.github.io/juki-hayami/`
  - URL を知っていれば誰でも見られる。カタログの数字と保有機種が見える程度なので問題なしと確認済み（2026-10-20 酒井さん）
- ファイル構成
  - `index.html` … 画面の作りだけ（データを直すときは触らない）
  - `juki.json` … 34台の寸法データ（数字の修正はここだけ）
  - `img/` … カタログのページ画像
  - `manifest.json`・`sw.js` … ホーム画面追加と電波なしで見るための設定
- iPhone・iPad: Safari で開いて「ホーム画面に追加」→ アイコンで起動
- 電波なし対応: 一度開けば画面・データ・画像を端末に覚えさせ、電波なしでも表示。電波のある所で開いたとき新しいデータがあれば自動で入れ替える
- 外部のライブラリやサーバーは使わない（壊れる所を減らす）
